# Task 2.1 — Worker: Page-Fetch Queue Consumer

## Description

Add a second RabbitMQ consumer to the worker that listens on the `page-fetch` queue. When a message arrives, the worker opens the URL with Playwright, waits for network idle, extracts the full HTML, page title, and detected interactive elements (buttons, links, inputs, images with alt text), then POSTs the result back to the backend.

## Changes

### Modify `worker/src/types.ts`
- Add `FetchRequestJob` interface: `{ requestId: string, url: string }`
- Add `FieldMapping` interface: `{ canonicalField, selector, type, attribute? }`
- Add `DetectedElement` interface: `{ tag: string, text: string, selector: string }`
- Add `FetchResultPayload` interface: `{ success, html?, title?, detectedElements?, error? }`

### Modify `worker/src/consumer.ts`
- Initialize second RabbitMQ channel for `page-fetch` queue
- Add `fetchPageConsumer()` that consumes from `page-fetch` queue with prefetch=1
- Route messages: detect message type (by presence of `requestId` vs `jobId`)
- Keep existing `scraping_jobs` consumer unchanged

### Modify `worker/src/scraper.ts`
- Add `fetchPage(url: string)` function:
  - Opens URL with Playwright
  - `waitForLoadState('networkidle')` with 30s timeout
  - Extracts `document.documentElement.outerHTML`
  - Extracts `document.title`
  - Builds `detectedElements[]` from interactive nodes:
    - `button`, `a[href]`, `input`, `img[alt]`, `[role="button"]`, etc.
  - Generates unique CSS selectors for each detected element (use id, nth-child, or class-based fallback)
  - Returns `{ html, title, detectedElements }`
  - On failure: returns error message
- Sanitize HTML before returning (strip `<script>` tags, remove event handlers)
