# Task 1.2 — Fetch-Page Backend Module

## Description

Create the `FetchModule` with controller, service, and DTOs for the page-fetch lifecycle. Exposes endpoints for frontend to request page rendering and for the worker to submit results. Publishers messages to the `page-fetch` RabbitMQ queue.

## Changes

### Create `backend/src/modules/fetch-page/`
- `fetch-page.module.ts` — NestJS module, imports PrismaModule + RabbitmqModule
- `fetch-page.controller.ts` — three endpoints:
  - `POST /api/fetch-page` — accepts `{ url }`, creates FetchRequest record, publishes to page-fetch queue, returns `{ id, status }`
  - `GET /api/fetch-page/:id` — returns FetchRequest with result (for polling)
  - `POST /api/fetch-page/:id/result` — worker callback, updates FetchRequest with HTML + detected elements
- `fetch-page.service.ts` — business logic: create request, publish message, update result
- `dto/create-fetch-page.dto.ts` — `{ url: string }` with validation
- `dto/submit-fetch-result.dto.ts` — `{ success, html?, title?, detectedElements?, error? }`
- `index.ts` — barrel exports

### Modify `backend/src/app.module.ts`
- Import and register `FetchModule`

### Modify `backend/src/common/rabbitmq/rabbitmq.config.ts`
- Add `pageFetchQueue: process.env.PAGE_FETCH_QUEUE || 'page-fetch'`

## Dependencies

## Acceptance Criteria

- [ ] `POST /api/fetch-page` creates FetchRequest with status `queued` and publishes to `page-fetch` queue
- [ ] `GET /api/fetch-page/:id` returns FetchRequest with current status
- [ ] `POST /api/fetch-page/:id/result` updates FetchRequest to `completed`/`failed` with result data
