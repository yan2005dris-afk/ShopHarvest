# Task 1.3 — Scrape-Listing Endpoint + Domain Rule Updates

## Description

Add `POST /api/scrape-listing` endpoint for batch listing scraping. Modify ScrapingJobsService to support `type: "listing"` jobs with fieldMappings in the queue message. Update DomainsService/Controller to accept `fieldMappings`, `containerSelector`, and `productLimit` in create/update payloads. Extend submitResult handler for batch product upsert from listing results.

## Changes

### Modify `backend/src/modules/scraping-jobs/scraping-jobs.service.ts`
- Add `enqueueListingJob(domainRuleId, url, limit?)`: validates DomainRule has fieldMappings + containerSelector, creates ScrapingJob with `type: "listing"`, publishes extended message with `containerSelector`, `fieldMappings[]`, `limit`, `type: "listing"`
- Modify `submitResult()`: detect `type: "listing"` from job record, iterate batch products array, upsert each via ProductsService

### Modify `backend/src/modules/scraping-jobs/scraping-jobs.controller.ts`
- Add `POST /api/scrape-listing` route mapping to new service method
- Input: `{ domainRuleId: string, url: string, limit?: number }`
- Output: `{ id: string, status: "queued", type: "listing" }`

### Modify `backend/src/modules/domains/domains.service.ts`
- Extend `create()` and `update()` parameter types to accept optional `fieldMappings`, `containerSelector`, `productLimit`
- Pass these fields through to Prisma create/update

### Modify `backend/src/modules/domains/domains.controller.ts`
- Extend `create()` and `update()` body types to include `fieldMappings`, `containerSelector`, `productLimit`
