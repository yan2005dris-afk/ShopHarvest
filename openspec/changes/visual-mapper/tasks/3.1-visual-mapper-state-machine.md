# Task 3.1 — VisualMapperComponent: State Machine + API Integration

## Description

Implement the full VisualMapperComponent with state machine, URL input, fetch-page integration, and status polling. This is the main frontend component that replaces the old url-input page.

## Changes

### Modify `frontend/src/app/pages/visual-mapper/visual-mapper.component.ts`
- Full rewrite from scaffold to state-machine-driven component
- States: `idle | fetching | preview | mapping | scraping | done | error`
- **IDLE state**: URL input form with validation + "Fetch Page" button
  - Validate URL format before calling API
  - On click: call `ApiService.fetchPage()`, transition to FETCHING
- **FETCHING state**: Display spinner, disable inputs
  - Poll `GET /api/fetch-page/:id` every 2s (max 30 attempts)
  - On completed: store HTML + detectedElements, transition to PREVIEW
  - On failed/timeout: transition to ERROR
- **PREVIEW + MAPPING states**: (detailed in subsequent tasks)
- **SCRAPING state**: 
  - Poll `GET /api/scraping-jobs/:id` every 3s (max 20 attempts)
  - Display job ID, progress indicator
  - On completed: transition to DONE
  - On failed: transition to ERROR
- **ERROR state**: Show error message + "Try Again" button → IDLE
- **DONE state**: Success message + link to `/products`

### Modify `frontend/src/app/pages/visual-mapper/visual-mapper.component.html`
- Template with `*ngIf` sections for each state
- IDLE: URL input, fetch button
- FETCHING: spinner overlay
- PREVIEW: iframe + sidebar (detailed in 3.3-3.5)
- MAPPING: field list + scrape button
- SCRAPING: job status display
- DONE: success notification
- ERROR: error message + retry

### Modify `frontend/src/app/pages/visual-mapper/visual-mapper.component.css`
- Full layout styles: sidebar, preview pane, status bar
- States-specific styles (spinner animation, transitions)
- Responsive layout

### Modify `frontend/src/app/services/api.service.ts`
- Add `fetchPage(url: string): Observable<FetchRequest>`
- Add `getFetchResult(id: string): Observable<FetchRequest>`
- Add `scrapeListing(domainRuleId: string, url: string, limit?: number): Observable<ScrapingJob>`
- Add `FetchRequest` interface to types
- Update `DomainRule` interface with optional `fieldMappings`, `containerSelector`, `productLimit`
